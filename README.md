# ВКР и проектный семинар

Один репозиторий для вашей ВКР в седьмом и восьмом семестрах. Каждый сдаваемый этап оформляется отдельным pull request (PR) в вашем репозитории. Исправления добавляются в тот же PR, после одобрения преподавателем он объединяется с `main`.

## С чего начать

1. Создайте **свой** репозиторий кнопкой **Use this template → Create a new repository**. Выберите **Public**, не включайте **Include all branches**. В организацию курса вступать не нужно.
2. Укажите рабочую тему и описание проекта внизу этой страницы.
3. Прочитайте [инструкцию для новичков](course/submission.md) и [карту заданий двух семестров](course/assignments.md).
4. В таблице курса укажите свой GitHub username и репозиторий. При каждой сдаче добавляйте ссылку на соответствующий **PR**. Ссылку на таблицу выдаёт преподаватель.

## В каком формате писать

Используйте удобный редактор. Принимаются отчёты **DOCX, PDF и Markdown**; презентации можно хранить в PPTX или PDF. Markdown не обязателен. Делать две версии одного документа не требуется. Если вы прикладываете исходник Word, можно также экспортировать PDF для просмотра, но это по желанию.

Можно написать один документ на несколько разделов и в описании PR указать, где смотреть каждый результат. Требования к оформлению из задания преподавателя остаются обязательными. Инструкции курса находятся в `course/`, ваши документы — в `docs/`.

## Где хранить материалы

| Папка | Содержание |
|---|---|
| [docs/research/](docs/research/) | Тема, обзор источников, аналоги, цель и задачи |
| [docs/requirements/](docs/requirements/) | Техническое задание и требования |
| [docs/design/](docs/design/) | Модели, диаграммы и архитектура |
| [docs/implementation/](docs/implementation/) | Реализация, запуск и проверка результата |
| [docs/results/](docs/results/) | Материалы ВКР и выбранного варианта восьмого семестра |
| [assets/](assets/) | Диаграммы и иллюстрации |
| [src/](src/) | Исходный код, если он нужен |

Названия папок отражают содержание работы, а не номера лабораторных. Структуру можно расширять под свою тему. Не создавайте копии одного отчёта для разных этапов: обновляйте его в рабочей ветке.

# Как сдать работу

Схема сдачи: **свой репозиторий → рабочая ветка → файлы → PR → ссылка в таблице → замечания → принятие**.

PR (pull request) — страница сдачи с файлами, историей исправлений и обсуждением. `main` — принятая версия вашей ВКР; рабочая ветка — изменения текущего этапа.

## Один раз перед первой сдачей

1. Создайте аккаунт [GitHub](https://github.com) и подтвердите почту.
2. Откройте [шаблон курса](https://github.com/project-seminar-2026/vkr-template), нажмите **Use this template → Create a new repository**. Выберите свой аккаунт, имя `vkr` и **Public**. **Include all branches** не включайте. В организацию курса вступать не нужно.
3. Запишите свой username и ссылку на репозиторий в таблицу курса. Ссылку на таблицу выдаёт преподаватель.
4. Укажите тему и короткое описание ВКР в README своего репозитория.
5. В [настройках уведомлений](https://github.com/settings/notifications) включите email для обсуждений, в которых участвуете. После сдачи проверяйте PR и почту.

Если репозиторий ВКР уже есть, согласуйте его использование с преподавателем. Переносить готовую работу только ради шаблона не нужно.

## Сдача через сайт

1. **Создайте ветку.** В своём репозитории откройте **Code**, нажмите переключатель `main`. Введите `s7-lab2` и выберите **Create branch … from main**. Для другого этапа поменяйте имя, например `s8-vkr-materials`.
2. **Загрузите работу.** Проверьте, что выбрана рабочая ветка. Откройте нужную папку в `docs/`, нажмите **Add file → Upload files**, выберите отчёт и сохраните через **Commit changes** в эту ветку. Можно сдавать DOCX, PDF или Markdown; две версии одного документа не требуются. Презентация — PPTX или PDF. Соблюдайте требования к оформлению из задания.
3. **Откройте PR.** Нажмите **Compare & pull request** или **Pull requests → New pull request**. Направление: **base: main**, **compare: ваша ветка**, обе в **вашем** репозитории. В заголовке укажите семестр и этап. Заполните описание по готовым подсказкам: что сдаёте, ссылки на файлы из рабочей ветки, вопросы. Нажмите **Create pull request**, без статуса Draft.
4. **Внесите ссылку в таблицу.** Скопируйте адрес PR — он содержит `/pull/` и номер. Вставьте в свою строку и колонку этапа. Ссылка на репозиторий не заменяет ссылку на PR.

## Замечания и следующий этап

Читайте отзыв на странице PR в **Conversation**. Для текстовых файлов замечания также могут быть на **Files changed**; для Word и PDF преподаватель укажет документ, страницу или раздел.

Исправьте работу и загрузите файл **под тем же именем, в ту же папку и ту же ветку**. PR обновится, ссылка останется прежней. Ответьте в обсуждении, что исправлено. Новый PR для доработки этой сдачи не нужен.

После одобрения актуальной версии преподавателем нажмите **Merge pull request → Confirm merge**. Возможность нажать Merge сама по себе не означает зачёт. Следующий этап начните новой веткой из обновлённой `main`.

<details>
<summary>Если удобнее работать через Git</summary>


Установите [Git](https://git-scm.com/downloads) и [GitHub CLI](https://cli.github.com). `YOUR_LOGIN` замените своим username, путь отчёта — своим файлом. Команды выполняйте по одной; при ошибке остановитесь.

Один раз войдите и скачайте **свой** репозиторий:

```bash
gh auth login --hostname github.com --git-protocol https --web
gh auth setup-git
gh repo clone YOUR_LOGIN/vkr
cd vkr
```

Для сдачи создайте ветку, сохраните в неё отчёт, затем отправьте изменения:

```bash
git switch main
git pull --ff-only
git switch -c s7-lab2
# Сохраните свой отчёт в docs/research/report.docx
git add docs/research/report.docx
git commit -m "Добавить обоснование темы"
git push -u origin s7-lab2
gh pr create --base main --head s7-lab2 --web
```

Заполните PR на сайте и внесите его ссылку в таблицу. Для исправлений замените файл в той же ветке, снова выполните `git add`, `git commit` и `git push`.

Если Git попросит имя и почту автора, укажите своё имя через `git config --global user.name "Ваше имя"`, а почту — через `git config --global user.email "YOUR_EMAIL"`. Для приватности можно взять адрес `noreply` из [настроек почты](https://github.com/settings/emails). Пароль GitHub для `git push` не используется.

</details>

## Важно

- Публичный репозиторий виден всем. Не загружайте скриншоты my.itmo.ru, личные документы, закрытые данные, пароли и ключи.
- Анкета и отчёт по ГИА сдаются отдельно; порядок обоих семестров — в [карте заданий](assignments.md).
- Отчёт должен быть в ветке PR, а не только вложением к комментарию. Для большого видео можно указать доступную преподавателю ссылку.
- Если сохранили всё в `main`, PR пустой или возник конфликт — не удаляйте работу и не используйте force push. Напишите преподавателю с ссылкой на репозиторий и текстом ошибки без секретов.
